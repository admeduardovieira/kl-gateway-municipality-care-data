## A. Загальний діагноз

### Виявлена архітектура
kl-gateway-municipality-care-data — це посібник реалізації (IG) FHIR R4 для даних модульних опаки KL Gateway, розроблений hl7dk (Kommunernes Landsforening, Данія). Збудований за допомогою SUSHI/FSH і публікується через IG Publisher. Це не виконувальний додаток: визначення FSH, інваріанти, сторінки документації та скрипти збирання IG Publisher.

Структура:
- `input/fsh/*.fsh` — 27 визначень FSH (профіли, розширення, набори значень, приклади: citizen.fsh, condition.fsh, encounter.fsh, goal.fsh,’observations, інтервенції, deliveryReport тощо)
- `input/pagecontent/index.md` — головна сторінка
- `input/ignoreWarnings.txt` — приглушені повідомлення про попередження
- `sushi-config.yaml` — конфігурація SUSHI (id, canonical, залежності, releaseLabel)
- `ig.ini` — конфігурація IG Publisher
- `_gencontinuous.bat/.sh`, `_genonce.bat/.sh`, `_updatePublisher.bat/.sh` — скрипі збирання IG Publisher
- `README.md` — мінімальний (лише посилання на build.fhir.org)

### Технології та залежності
- FHIR R4 (4.0.1)
- SUSHI (FSH)
- Залежності: `hl7.fhir.dk.core` (закріплено на 1.1.0), `dk.fhir.ig.kl.common.caresocial: current` (не закріплено)
- `ig.ini`: `template = fhir.base.template#current` (шаблон не закріплено)
- releaseLabel: `ci-build` (правильне написання)

### Деталі

**REA-016 — Залежність не закріплена (ПРОПОЗИЦІЯ)**
- Проблема: `sushi-config.yaml` оголошує `dk.fhir.ig.kl.common.caresocial: current`.
- Довід: `sushi-config.yaml:18-22`. (`hl7.fhir.dk.core` закріплено на 1.1.0, добра практика, але `dk.fhir.ig.kl.common.caresocial` ні.)
- Причина: версія не закріплена в конфігурації SUSHI.
- Наслідок: нерозтовшуючі збирання; ризик пошкодження в результаті несумісних змін зверху.
- Пропонована виправка: замінити `current` на конкретну стабільну версію після перевірки доступності в реєстрі FHIR.

**REA-017 — Шаблон не закріплено (ПРОПОЗИЦІЯ)**
- Проблема: `ig.ini` оголошує `template = fhir.base.template#current`.
- Довід: `ig.ini:3`.
- Причина: версія шаблону IG Publisher не закріплена.
- Наслідок: збирання можуть використовувати різні версії шаблону, створюючи неконсистентний вивід.
- Пропонована виправка: замінити `current` на конкретну стабільну версію після перевірки доступності.

**REA-018 — Відсутність CI/CD та автоматизованих тестів (ПРОПОЗИЦІЯ)**
- Проблема: немає `.github/workflows`, тестів ani package.json.
- Довід: відсутність директорії `.github` ani файлів тестів.
- Причина: у IG немає конвеєра неперервної інтеграції.
- Наслідок: зміни у FSH не валідуються автоматично.
- Пропонована виправка: додати робочий процес CI, який запускає SUSHI та валідує IG (потребує SUSHI на ran-ері).

**REA-019 — майже порожній README (ПРОПОЗИЦІЯ)**
- Проблема: `README.md` містить лише посилання на build.fhir.org, без інструкцій із встановлення/збирання/тестів/побідування участі.
- Довід: `README.md` (6 рядків, 4 порожні).
- Причина: недостатня документація.
- Наслідок: затримка в адаптації учасників.
- Пропонована виправка: розширити README інструкціями зі встановлення, збирання, тестів та побідування участі.
